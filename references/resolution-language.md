# 自然语言尺寸映射

## 优先级

1. 明确像素尺寸最高，例如 `12000×5000`、`宽 12000，高 5000`。
2. 明确倍率其次，例如“放大两倍”或“扩大 1.5 倍”。倍率同时作用于宽和高，并将结果确定性取整。
3. `4K`、`8K`、`16K` 是长边目标，分别映射为 4096、8192、16384 px；短边按输入比例计算。
4. 单独说“高清”“超清”“高分辨率”时，默认宽高各放大 2 倍。

如果一条请求同时包含这些表达，采用优先级更高的规则，并在报告中保留原文和采用理由。不要把“8K”解释成固定的 16:9，也不要为了凑整把明确尺寸改成最接近的 4K/8K/16K。

## 目标尺寸和原生细节不是同一件事

`target_width` / `target_height` 是交付画布的像素尺寸；`native_width` / `native_height` 是图像生成工具实际返回的每片像素尺寸。目标画布可以通过许多独立 tile 覆盖，但这不会自动证明每个像素都有原生 8K/16K 级别的细节。

Skill 必须先探测一次真实返回尺寸，再决定网格。实际返回尺寸小于 manifest 的 crop 时，停止；不允许隐式 resize、插值超分、JPEG 重编码，或把放大结果标成“原生 16K”。

## 示例

以下以 `2132×738` 的横幅为例，实际数字应以 `sips` 或生成器返回的尺寸为准：

| 用户说法 | mode | 目标尺寸 |
| --- | --- | --- |
| 高清 | scale | `4264×1476` |
| 放大两倍 | scale, scale=2 | `4264×1476` |
| 8K | long_edge | `8192×2836` |
| 16K | long_edge | `16384×5671` |
| 宽 12000，高 5000 | explicit | `12000×5000` |

倍率和长边模式要记录完整的 request 对象。显式尺寸即使改变原图比例也照做，同时在质量报告中标注 `aspect_ratio_changed` 或等效说明。
